# Theme presets

The **Preset** dropdown in the toolbar above snaps all six `<al-theme>` axes at once —
`brand` + `mode` + `density` + `contrast` + `shape` + `motion` (the last two added by spec
2026-08-20-token-axes-expansion). One click moves the whole canvas to a different,
intentional look instead of asking you to tune six knobs into a combination nobody designed.

A preset is nothing more than a **named tuple of values `<al-theme>` already accepts**. There is
no "preset" concept in the token layer, the emitter, the DTCG source, or the component API. See
[`AXES.md`](../../../../.altitude/AXES.md) for the `shape`/`motion` axis model and the
brand-as-recipe rule ("a brand look is brand + mode + density + shape + motion, never one
attribute flip").

## The presets that ship

| id | brand | mode | density | contrast | shape | motion |
| --- | --- | --- | --- | --- | --- | --- |
| `altitude-dark` *(default)* | altitude | dark | — | — | — | — |
| `altitude-light` | altitude | light | — | — | — | — |
| `southleft-dark` | southleft | dark | — | `more` | — | — |
| `altitude-dark-playful` | altitude | dark | — | — | `pill` | `expressive` |
| `altitude-dark-brutalist` | altitude | dark | `compact` | — | `sharp` | — |
| `southleft-dark-calm` | southleft | dark | — | `more` | — | `reduced` |

The first three entries — one per emitted brand × mode bundle — stay legibly parallel with the
`BRANDS` table inside `<al-theme-switcher>`. The three recipe presets are documented in full in
`AXES.md` §3; `altitude-dark-brutalist` is the compact+sharp recipe re-homed from the cut
northright brand (spec 2026-08-20-brand-pruning-and-storybook-de-bloat) so `shape: 'sharp'` still
has a preset.

The `density` / `contrast` choices are not decoration. Each is the axis that matches that brand's
archetype in `.altitude/BRANDS.md` §7: southleft is the *high-contrast utilitarian* brand, so it
carries `contrast: 'more'`.

## Adding a preset

One line, in one file — `libs/al-web-components/.storybook/presets.ts`:

```ts
export const PRESETS: Preset[] = [
  // …
  { id: 'southleft-dark-cozy', label: 'Southleft · Dark · Cozy', brand: 'southleft', mode: 'dark', density: 'cozy' },
];
```

The toolbar item, the decorator and the story wrapper are all derived from that array. Nothing
else changes.

### Constraint: the brand + mode pair must have an emitted bundle

Only three bundles exist, because only three `{ theme, brand }` entries are built by the `brands`
array in `styles/tokens-config.v5.mjs`:

| bundle | brand | mode |
| --- | --- | --- |
| `styles/dist/scss/brand/tokens-altitude-light.scss` | altitude | light |
| `styles/dist/scss/brand/tokens-altitude-dark.scss` | altitude | dark |
| `styles/dist/scss/brand/tokens-southleft-dark.scss` | southleft | dark |

**Southleft is dark-only** (its light "paper" mode is owned by the Southleft Example App spec).
Naming `brand: 'southleft', mode: 'light'` is a TypeScript error, not a runtime surprise — the
`PresetBundle` union in `presets.ts` is the guard. Emitting the missing light build is
token-pipeline work, not Storybook work.

### `density` and `contrast`

Both are optional. `density` used to be a trap: `:host([density='comfortable'])` wrote
`--al-theme-space-md: 1rem` where the bundle says 1.25rem, so naming the axis at its *own default
value* silently reflowed the story — which is why five of these six presets left it off. That rule
is now deleted. The base ramp **is** comfortable, so omitting `density` and writing
`density="comfortable"` are the same thing, and `compact` / `cozy` shrink from there.
See `.altitude/BRANDS.md` §4.

`contrast="normal"` matches no rule at all, so only `contrast: 'more'` is worth writing.

## Prerequisite: build the tokens first

`styles/dist/` and `styles/dist-v5/` are **generated, gitignored build artifacts**. A fresh clone
has neither, and `components/theme/theme.scss` `@use`s the scoped host partials out of
`styles/dist-v5/scss/host/` — so without them Storybook does not render a degraded toolbar, it
fails to compile any component at all:

```bash
pnpm --filter al-web-components build:tokens
```

`.storybook/main.ts` checks for the artifact in Node before the dev server boots and fails with
that exact command rather than a bare Vite "failed to resolve import". CI is already correct: the
root `build:storybook-web-components` runs after `pnpm run build`, which chains `build:tokens`
first.

## How a preset reaches the canvas

**One mechanism: six attributes on one `<al-theme>` element.**

| axis | delivered by |
| --- | --- |
| `brand` | generated `:host([brand='x'])` + `:host([brand='x'][mode='y'])` blocks in `<al-theme>`'s own styles |
| `mode` | generated `:host([mode='y'])` block, same place |
| `density`, `contrast` | hand-written `:host([density])` / `:host([contrast])` rules in `theme.scss` |
| `shape`, `motion` | hand-written `:host([shape])` / `:host([motion])` rules in `theme.scss`, read by components via `var(--…-role-x, var(--…-legacy))` fallback — see `AXES.md` §2.3 for why the role tokens carry no `:root` default of their own |

The brand and mode blocks come from `styles/tokens-config.v5.mjs` into
`styles/dist-v5/scss/host/` and reach the component through one `@use` in `theme.scss`. They are
**deltas** — each restates only what differs from the base `:root` bundle the page already loads,
which is what keeps the whole matrix at ~16 KB instead of ~105 KB. The corollary: `<al-theme>`
*composes on top of* a base token sheet, it does not replace one.

This decorator used to swap a whole `:root` stylesheet into `<head>` to deliver `brand`, with an
always-last ordering guard, because no `:host([brand])` rule existed. That is gone, along with the
`style#al-preset-tokens` element. No global state is left, so nothing leaks out of the wrapper.

`<al-theme>` uses `display: contents`, so the wrapper is layout-neutral. Note that the two
brands genuinely differ in **size** (type ramp, spacing, radius), so switching preset reflows the
story — that is the payload, not a bug.

### Stylesheet ownership

| element | owner | rule |
| --- | --- | --- |
| `style#al-theme-sheet` | `.storybook/preview.ts` | `main.scss` + the default altitude-dark `:root` block. The decorator never touches it. |
| `style#al-docs-reskin` | `.storybook/preview-head.html` | The docs/story chrome (`--al-docs-*` on `:root`). Deliberately NOT `--al-theme-*`, so the frame stays constant while the preset changes. |
| `style#al-tokens-sheet` | `<al-theme-switcher>` | The **deprecated** global-swap fallback; only reachable when no `<al-theme>` ancestor exists. |

The `style#iconfont-style` row is gone: the icon webfont was removed with the
Phosphor migration and `preview.ts` no longer injects it.

The decorator owns no `<style>` element at all any more.

### The AI Theme engine (no longer a Storybook console)

Spec 2026-08-20-brand-pruning-and-storybook-de-bloat removed the manager-panel
UI that used to sit in the toolbar (`◐`) and derive a palette from a prompt —
Storybook is documentation now, not a synthetic-brand showcase. The engine it
was built on (`.storybook/ai-theme/{engine,oklch,ramps,personalities,
constants,types,apply}.ts`) is unchanged and still backs the `/api/theme`
endpoint (`functions/api/theme.js`, mounted locally by
`.storybook/ai-theme/vite-plugin-theme-api.ts`) — a shipping product feature
the upcoming Southleft example app consumes. It no longer writes into the
preview iframe from inside Storybook.

## Opting a story out

```ts
export default {
  title: 'Molecules/My Component',
  parameters: {
    alPreset: { disable: true },
  },
};
```

The decorator then renders the story with no `<al-theme>` wrapper at all, so it inherits the
document's `:root` tokens exactly as it does on `main`.

The `<al-theme-switcher>` stories use this, so that the component's own deprecated global-swap
fallback stays reachable in its own story instead of being short-circuited by a wrapper.

Elsewhere the switcher is now **fully** functional inside a preset-wrapped story: it sets `brand`
and `mode` on the wrapper it finds and both are host rules, so both visibly move. Before scoped
emission only `mode` did — the brand half needed a global sheet the switcher's scoped path
deliberately does not touch.

## Known limits

- **The Storybook chrome stays dark.** The manager theme is hardcoded (`.storybook/theme.js`).
  A preset changes the preview iframe only; re-theming the manager is out of scope.
- **One preset per iframe** — the toolbar is a single global, so a docs page's stories all share
  it. That is now a *toolbar* limit and not a technical one: `brand` is a `:host` rule, so two
  `<al-theme>` subtrees on one page genuinely compute different values. Proof:
  `.altitude/visual-compare/brands.scoped.png`, asserted by `pnpm test:scoped-theming`.
- **`<al-theme>` is a delta, not a bundle.** The scoped blocks restate only what differs from the
  base `:root` sheet, so a page that loads no Altitude CSS gets an `<al-theme>` with nothing to
  resolve against. Keep `main.css` (or some `:root` bundle) loaded.
- **A brand with no build for a mode has no block for it.** Southleft is dark-only, so
  `<al-theme brand="southleft" mode="light">` renders southleft's type/radius/spacing over the
  light colour surface. The `PresetBundle` union makes that unreachable from a preset.
