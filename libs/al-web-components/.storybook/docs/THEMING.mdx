# Theme presets

The **Preset** dropdown in the toolbar above snaps all four `<al-theme>` axes at once —
`brand` + `mode` + `density` + `contrast`. One click moves the whole canvas to a different,
intentional look instead of asking you to tune four knobs into a combination nobody designed.

A preset is nothing more than a **named tuple of values `<al-theme>` already accepts**. There is
no "preset" concept in the token layer, the emitter, the DTCG source, or the component API.

## The presets that ship

| id | brand | mode | density | contrast |
| --- | --- | --- | --- | --- |
| `altitude-dark` *(default)* | altitude | dark | — | — |
| `altitude-light` | altitude | light | — | — |
| `northright-dark` | northright | dark | `compact` | — |
| `northright-light` | northright | light | `compact` | — |
| `odyssey-dark` | odyssey | dark | — | — |
| `southleft-dark` | southleft | dark | — | `more` |

Six entries — one per emitted brand × mode bundle, so this list stays legibly parallel with the
`BRANDS` table inside `<al-theme-switcher>`.

The `density` / `contrast` choices are not decoration. Each is the axis that matches that brand's
archetype in `.altitude/BRANDS.md` §7: northright is the *dense
operational* brand, so it carries `density: 'compact'`; southleft is the *high-contrast
utilitarian* brand, so it carries `contrast: 'more'`. Odyssey is *airy editorial* and already
ships a wider spacing ramp of its own — a `density` attribute could only shrink it, so it has
none.

## Adding a preset

One line, in one file — `libs/al-web-components/.storybook/presets.ts`:

```ts
export const PRESETS: Preset[] = [
  // …
  { id: 'odyssey-dark-cozy', label: 'Odyssey · Dark · Cozy', brand: 'odyssey', mode: 'dark', density: 'cozy' },
];
```

The toolbar item, the decorator and the story wrapper are all derived from that array. Nothing
else changes.

### Constraint: the brand + mode pair must have an emitted bundle

Only six bundles exist, because only six `{ theme, brand }` entries are built by the `brands`
array in `styles/tokens-config.v5.mjs`:

| bundle | brand | mode |
| --- | --- | --- |
| `styles/dist/scss/brand/tokens-altitude-light.scss` | altitude | light |
| `styles/dist/scss/brand/tokens-altitude-dark.scss` | altitude | dark |
| `styles/dist/scss/brand/tokens-northright-light.scss` | northright | light |
| `styles/dist/scss/brand/tokens-northright-dark.scss` | northright | dark |
| `styles/dist/scss/brand/tokens-odyssey-dark.scss` | odyssey | dark |
| `styles/dist/scss/brand/tokens-southleft-dark.scss` | southleft | dark |

**Odyssey and Southleft are dark-only.** Naming `brand: 'southleft', mode: 'light'` is a
TypeScript error, not a runtime surprise — the `PresetBundle` union in `presets.ts` is the guard.
Emitting the missing light builds is token-pipeline work, not Storybook work.

### Careful with `density`

`density` is **optional and usually omitted**, on purpose. `:host([density])` hardcodes
`--al-theme-space-{sm,md,lg}` in `components/theme/theme.scss`, and those hardcodes do **not**
match the emitted bundle: the bundle ships `sm: 0.75rem / md: 1.25rem / lg: 1.5rem`, while
`density="comfortable"` writes `0.75 / 1 / 1.5rem`. So `density="comfortable"` is *not* a no-op —
it silently shrinks `--al-theme-space-md`. A preset that leaves `density` undefined renders
exactly what the bundle says. See `.altitude/BRANDS.md` §4.

`contrast="normal"` matches no rule at all, so only `contrast: 'more'` is worth writing.

## Prerequisite: build the tokens first

`styles/dist/` is a **generated, gitignored build artifact**. A fresh clone does not have it, and
the preset config reads the brand bundles out of it:

```bash
pnpm --filter al-web-components build:tokens
```

`.storybook/main.ts` checks for the artifact in Node before the dev server boots and fails with
that exact command rather than a bare Vite "failed to resolve import". CI is already correct: the
root `build:storybook-web-components` runs after `pnpm run build`, which chains `build:tokens`
first.

## How a preset reaches the canvas

Two mechanisms, both required, because the axes are not delivered the same way:

| axis | delivered by | why |
| --- | --- | --- |
| `brand` | global stylesheet swap | Every bundle is emitted as an unlayered `:root` block and `theme.scss` has **no** `:host([brand])` rule, so the attribute alone styles nothing. |
| `density`, `contrast` | attribute on `<al-theme>` | Host rules only; no bundle varies by either. |
| `mode` | **both** | The host rule carries two custom properties; the per-mode bundle carries the whole surface. |

`<al-theme>` uses `display: contents`, so the wrapper is layout-neutral. Note that the four
brands genuinely differ in **size** (type ramp, spacing, radius), so switching preset reflows the
story — that is the payload, not a bug.

### Stylesheet ownership

| element | owner | rule |
| --- | --- | --- |
| `style#al-theme-sheet` | `.storybook/preview.ts` | `main.scss` + the default altitude-dark `:root` block. The decorator never touches it. |
| `style#iconfont-style` | `.storybook/preview.ts` | Never touched. |
| `style#al-preset-tokens` | `.storybook/with-preset.ts` | Exactly one, re-appended so it stays after every other stylesheet in `<head>`. |
| `style#al-tokens-sheet` | `<al-theme-switcher>` | Distinct id; the two never clobber each other. |

`style#al-theme-sheet` and `style#al-preset-tokens` are unlayered `:root` rules of identical
specificity, so **document order decides and last wins**. That is why the decorator re-appends
rather than mutating in place.

## Opting a story out

```ts
export default {
  title: 'Molecules/My Component',
  parameters: {
    alPreset: { disable: true },
  },
};
```

The decorator then skips **both** halves — no `<al-theme>` wrapper and no token swap — and
removes any `style#al-preset-tokens` left behind by the previously viewed story.

The `<al-theme-switcher>` stories use this. That component walks up for an `<al-theme>` ancestor
and takes its scoped path when it finds one, and its own `style#al-tokens-sheet` would land
*before* the decorator's always-last block — so with the decorator active its menu would look
broken in its own story.

Note the consequence elsewhere: inside any *other* preset-wrapped story that embeds
`<al-theme-switcher>` (the Dashboard template, for example), the in-canvas switcher finds the
decorator's wrapper and takes the scoped path, so only `mode` visibly moves. Use the toolbar for
brand.

## Known limits

- **The Storybook chrome stays dark.** The manager theme is hardcoded (`.storybook/theme.js`).
  A preset changes the preview iframe only; re-theming the manager is out of scope.
- **One preset per iframe.** A docs page renders many stories into one iframe, so they all share
  the selected preset. Two brands side by side on one page needs scoped token emission
  (`:host([brand])` rules), which does not exist yet.
- **`mode` on the wrapper is worth 2 properties.** `:host([mode='dark'])` hardcodes
  `--al-theme-color-background-default: #161616` and `--al-theme-color-content-default: #f4f4f4`,
  while the dark bundle resolves those to `#181818` / `#f8f8f6`. Inside the wrapper the host rule
  wins. No brand overrides either token, so nothing brand-specific is lost.
